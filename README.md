# Verde Marea

Verde Marea — локальный проект системы бронирования столов средиземноморского ресторана для финального задания Яндекс Практикума. В приложении доступны стартовая страница, регистрация, вход и личный кабинет. Сценарии гостей и сотрудников описаны в документации этапа 1.

Стек проекта — Next.js (App Router), React, TypeScript, Tailwind CSS v4, ESLint и npm. Окружение проверено на Node.js 24.22.2.

## Локальный запуск

```sh
npm ci
npm run dev -- --webpack
```

Приложение доступно по адресу http://localhost:3000.

## Локальная база данных

Для миграций и демонстрационных данных нужен PostgreSQL 16 и отдельная база Verde Marea. Подставь имя своей локальной роли вместо `YOUR_DB_USER`. Если роль не может создать базу, её создаёт локальный администратор с этой ролью в качестве владельца.

```sh
createdb -h 127.0.0.1 -U YOUR_DB_USER verde_marea_dev
cp -i .env.example .env
```

Заполни `DATABASE_URL` и три переменные `SEED_*_PASSWORD` в локальном `.env`. Для пароля в URL используй percent-encoding. После установки зависимостей через `npm ci` выполни из папки проекта:

```sh
npm exec -- prisma migrate deploy
npm exec -- prisma generate
npm exec -- prisma db seed
npm exec -- prisma migrate status
```

Демонстрационные аккаунты предназначены для локальной базы. Проверка на отдельной тестовой базе описана в [документации Prisma](prisma/README.md#проверка-на-отдельной-базе).

## Авторизация

На странице `/register` укажи имя, email и пароль. После регистрации войди на `/login`. Страница `/account` показывает email и позволяет завершить текущую сессию. Для входа также подходят локальные аккаунты из seed.

Email очищается от пробелов по краям и приводится к нижнему регистру. Поддерживаются непустые пароли длиной до 72 байт UTF-8. Сессия действует семь суток с момента входа. Production-cookie требует HTTPS.

Страница `/admin` доступна для `admin` и `super_admin`. Обработчик `GET /api/admin/access` проверяет сессию и роль при каждом запросе. Он возвращает только текущую роль сотрудника, а при отказе отвечает `401` или `403`.

Защищённая страница кабинета получает аккаунт из `requireSignedInUser()`. Административные страницы и обработчики вызывают `checkAdminAccess()` перед выдачей данных. Будущие операции дополнительно проверяют права на конкретное действие и ресурс. Для критической записи эти проверки выполняются по актуальным данным в транзакции вместе с записью.

Команда `npm run test:auth` запускает тесты валидации, сессий и правил доступа. Для тестов с PostgreSQL задай `AUTH_TEST_DATABASE_URL` для отдельной тестовой базы с применёнными миграциями. Для HTTP-теста также задай `AUTH_TEST_APP_URL` с адресом запущенного приложения, подключённого к этой же тестовой базе. Тесты удаляют созданные ими аккаунты и сессии.

## API доступности

Любой посетитель может вызвать `GET /api/availability?date=2026-11-24&guests=2`.
`date` — календарная дата ресторана в формате `YYYY-MM-DD`, `guests` —
положительное целое число. `RESTAURANT_TIME_ZONE` задаёт зону расписания.
По умолчанию используется `Europe/Moscow`.

Пример ответа `200 OK` для даты в пределах горизонта, когда свободно одно окно:

```json
{
  "status": "available",
  "slots": [
    { "startsAt": "2026-11-24T09:00:00.000Z", "endsAt": "2026-11-24T10:30:00.000Z" }
  ]
}
```

Границы окна передаются в ISO 8601 в UTC. В примере это 12:00–13:30 по Москве.
Ответы `200 OK` с пустым `slots` содержат один из следующих статусов.

| Статус | Значение |
| --- | --- |
| `closed` | Понедельник или закрытия перекрывают все оставшиеся окна |
| `outside_horizon` | Дата раньше сегодняшней или позже 13-й календарной даты после неё |
| `no_availability` | Будущих окон либо свободных столов нужной вместимости нет |

Некорректные параметры возвращают `400 Bad Request` со статусом `invalid_input`
и текстовым полем `error`. Ответы не кэшируются. Доступность предварительная.
При создании брони сервер повторяет проверку в транзакции `Serializable`.

Для интеграционных тестов доступности примени обе миграции к отдельной пустой
`verde_marea_availability_test` без seed. Передай её URL через
`AVAILABILITY_TEST_DATABASE_URL` и запусти `npm run test:availability`.
Записи интеграционного расчёта откатываются, а временный стол HTTP-обработчика
удаляется после проверки. Без переменной выполняются проверки календаря
и API, которым не требуется PostgreSQL. Для проверки часового пояса процесса
запусти команду с `TZ=America/Los_Angeles`.
